# Notion Setup Steps for V1.2 Reporting

**Purpose:** Set up the Notion workspace that the autonomous agent writes milestone events and daily/weekly summaries to.

**Integration:** The agent's `notion-reporter.ts` uses the Notion API to write structured data. It needs 2 things created in Notion: a **Milestones database** and a **Monthly Summaries page**. After creation, their IDs go into the agent's `.env` file.

---

## Step 1: Create the Milestones Database

Create a **full-page Notion database** (not inline) in your workspace. This database receives one row per agent event (task started, completed, failed, blocked, step completed).

### Database Name
`Agent Milestones`

### Properties to Create

Create these properties exactly as specified — the property **names are case-sensitive** and must match exactly:

| Property Name | Property Type | Configuration |
|---------------|---------------|---------------|
| `Title` | **Title** | (default, already exists on every database) |
| `Event` | **Select** | Add these options: `Started`, `Completed`, `Failed`, `Blocked`, `Step Completed` |
| `Priority` | **Select** | Add these options: `P0`, `P1`, `P2`, `P3`, `P4` |
| `Timestamp` | **Date** | Default date format, include time |
| `Duration` | **Number** | Number format: "Number" (no units suffix needed — values are in minutes) |
| `Contract ID` | **Rich text** | Plain rich text (this stores the worker log reference, e.g. `task-b25db16e`) |
| `Output Path` | **Rich text** | Plain rich text (stores the file path to project output directory) |
| `Error Summary` | **Rich text** | Plain rich text (stores first 200 chars of error message for failures) |

### Select Option Colors (Optional but Recommended)

**Event options:**
- `Started` → Blue
- `Completed` → Green
- `Failed` → Red
- `Blocked` → Orange
- `Step Completed` → Purple

**Priority options:**
- `P0` → Red (Critical)
- `P1` → Orange (Urgent)
- `P2` → Yellow (High)
- `P3` → Blue (Normal)
- `P4` → Gray (Low)

### Recommended Views

1. **Default table view** — All columns visible, sorted by `Timestamp` descending
2. **Board view** — Group by `Event`, useful for seeing what's in progress vs completed
3. **Filter view: Active** — Filter where `Event` is `Started` or `Step Completed`, sorted by `Timestamp` descending

### After Creation: Copy the Database ID

1. Open the database as a full page
2. Look at the URL: `https://www.notion.so/your-workspace/DATABASE_ID?v=...`
3. The **DATABASE_ID** is the 32-character hex string before the `?v=` parameter
4. Example: `https://www.notion.so/workspace/a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4?v=...` → ID is `a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4`

Save this — it goes into `NOTION_DATABASE_ID` in `.env`.

## Step 2: Create the Monthly Summaries Page

Create a **regular Notion page** (not a database). The agent appends daily summary blocks to this page and creates weekly summary child pages under it.

### Page Name
`Agent Summaries — January 2026`

(Update the month/year as needed. You can create a new page each month.)

### Page Content (Starting Template)

The page can start empty or with a simple header:

```
# Agent Summaries — January 2026

Daily and weekly summaries auto-generated by the executive agent.
```

The agent will append content blocks to this page:
- **Daily summaries** are appended as `## Daily Summary: 2026-01-28` heading blocks with stats paragraphs
- **Weekly summaries** are created as child pages titled `Weekly Summary: 2026-01-21 to 2026-01-28`

### After Creation: Copy the Page ID

1. Open the page
2. Click the `...` menu (top right) → "Copy link"
3. The URL looks like: `https://www.notion.so/your-workspace/Agent-Summaries-PAGE_ID`
4. The **PAGE_ID** is the 32-character hex string at the end (may have dashes — remove them, or use as-is; the API accepts both formats)
5. Alternative: from the URL `https://www.notion.so/workspace/Agent-Summaries-January-2026-a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4` → ID is `a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4`

Save this — it goes into `NOTION_MONTHLY_PAGE_ID` in `.env`.

## Step 3: Verify Integration Access

The agent's Notion integration (connected via `NOTION_API_KEY` in `.env`) must have access to both the database and the page.

### Grant Access to the Milestones Database

1. Open the `Agent Milestones` database
2. Click the `...` menu (top right) → "Connections" (or "Connect to")
3. Find and add your integration (the one whose API key is in `.env`)
4. The integration needs **Read & Write** permissions (which is the default for internal integrations)

### Grant Access to the Monthly Summaries Page

1. Open the `Agent Summaries — January 2026` page
2. Click the `...` menu (top right) → "Connections"
3. Add the same integration
4. Same permissions: Read & Write

**If the integration doesn't appear:** Go to [notion.so/my-integrations](https://www.notion.so/my-integrations), verify the integration exists and has "Read content", "Update content", and "Insert content" capabilities enabled.

## Step 4: Update Agent .env File

Add these 3 lines to `/Users/jackjin/dev/continuous-agent/.env`:

```bash
NOTION_DATABASE_ID=<paste-milestones-database-id-here>
NOTION_MONTHLY_PAGE_ID=<paste-monthly-summaries-page-id-here>
NOTION_REPORTING_ENABLED=true
```

### What Each Variable Does

| Variable | Required? | What Happens If Missing |
|----------|-----------|------------------------|
| `NOTION_API_KEY` | Yes (already set) | All Notion reporting disabled silently |
| `NOTION_DATABASE_ID` | Yes | Milestone events (Started, Completed, etc.) not recorded |
| `NOTION_MONTHLY_PAGE_ID` | Yes | Daily and weekly summaries not posted |
| `NOTION_REPORTING_ENABLED` | No | Defaults to `true`. Set to `false` to disable all Notion reporting as a kill switch |

### Behavior Without These Variables

The agent runs fine without Notion configured. The reporter checks for these values on every call and silently returns if they're missing. Local ledgers (`work-ledger.jsonl`, `capability-ledger.jsonl`) remain the source of truth regardless.

## Step 5: Verify (After Agent Starts)

After the agent runs its first task, verify:

1. **Milestones database** should have a new row with:
   - Title: the task name (e.g., "Spotify-Inspired Music Player UI")
   - Event: "Started"
   - Priority: "P3"
   - Timestamp: current datetime

2. **Monthly summaries page** — Daily summary appears at end of day (or when the agent crosses a day boundary)

3. **Agent logs** — Check for lines like:
   ```
   [DETERMINISTIC] Notion milestone reported: Started - Spotify-Inspired Music Player UI
   ```
   Or if something fails:
   ```
   Notion milestone report failed (non-blocking): ...
   ```

## Summary of What You Need

After completing all steps, you should have:

| Item | Where It Lives | What the Agent Does With It |
|------|----------------|---------------------------|
| **Agent Milestones** database | Notion workspace | Inserts one row per milestone event (start/complete/fail/block/step) |
| **Agent Summaries** page | Notion workspace | Appends daily summary blocks; creates weekly summary child pages |
| `NOTION_DATABASE_ID` | `.env` | Points reporter to the milestones database |
| `NOTION_MONTHLY_PAGE_ID` | `.env` | Points reporter to the summaries page |
| `NOTION_REPORTING_ENABLED=true` | `.env` | Enables the reporter |
| Integration connection | Both database + page | Grants API write access |

## Data Flow Reference

```
Agent Executive Loop
    │
    ├── Phase 5 (Execute): reportMilestone('Started', ...)    ──► Milestones DB row
    │
    ├── Phase 6 (Success): reportMilestone('Completed', ...)  ──► Milestones DB row
    │                       reportMilestone('Step Completed')  ──► Milestones DB row
    │
    ├── Phase 6 (Failure): reportMilestone('Failed', ...)     ──► Milestones DB row
    │
    ├── Phase 6 (Blocked): reportMilestone('Blocked', ...)    ──► Milestones DB row
    │
    ├── Day boundary:      reportDailySummary()                ──► Appended blocks on Monthly Page
    │
    └── Weekly (Sunday):   reportWeeklySummary()               ──► Child page under Monthly Page
```

All Notion writes are fire-and-forget. If the API fails, the agent logs the error and continues. Local JSONL ledgers are always the source of truth.
